# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

A rebuild of the UNHEARD website — a ₹1,200 physical learning-discovery kit for
children aged 4–12 who learn differently, sold to parents in India.

Vanilla HTML/CSS/JS. **No framework, no build step, no dependencies** for the
site itself. Keep it that way.

## Commands

```bash
node serve.js        # dev server -> http://localhost:4321
node build-lib.js    # -> site/activities.html  (45 activities from JSON)
node build-pages.js  # -> site/kit.html, about.html, contact.html, 404.html
```

There is no test runner and no linter.

## Generated pages — read this before editing HTML

Only `site/index.html` is hand-written. These five are **generated**, and
editing them directly means the change is lost on the next build:

| File | Generated by |
|---|---|
| `site/activities.html` | `build-lib.js` (data: `site/js/activities.json`) |
| `site/kit.html`, `about.html`, `contact.html`, `404.html` | `build-pages.js` |

Edit the generator, then re-run it. The nav and footer markup is defined inside
both builders, so a change to either must be made in `build-lib.js` **and**
`build-pages.js`.

## Architecture

**Tokens.** `site/css/tokens.css` holds every colour, size, easing and font.
Nothing else holds a literal value. If you need a new value, add a token.

**Night theming** works by re-pointing the *same* token names under `.on-night`,
so any component dropped inside adapts with zero variant classes. Do not write
`.night .card {}` style overrides.

**CSS load order** is `tokens → app → parts → material → (page css)`. Several
rules depend on this; `parts.css` beats `app.css` at equal specificity by source
order alone.

**JS modules** in `site/js/app.js` are defensive IIFEs that early-return when
their markup is absent, so one script serves every page.

## Colour rules

Three hues, three jobs. **Violet leads** (brand, primary action), **emerald
confirms** (verified / sourced / real), **amber lifts** (warm human moments:
free things, the child's own work). Amber is a splash and never a system role —
at most three amber elements on one screen.

**A fill value is never text.** Every hue ships as a `fill / text / night`
triplet and they are not interchangeable. Emerald fill on white is 3.25:1;
`--grow-text` exists because of that. Text values are solved against
`--g-sunken`, the darkest light ground, so one token is safe on every light
surface.

**Never** use `--ink-ghost` as text (2.02:1). It is for rules and disabled
states only.

## Design constraints

`BRAND.md` and `DESIGN-BRIEF.md` are the reasoning behind everything in `site/`.
Read them before changing visual direction. The NEVER list in `BRAND.md` §5 is
binding — most of those entries exist because the thing was tried and measured
as a failure.

The most important one: **never reintroduce the jigsaw puzzle mark.** The
original site used the autism-awareness puzzle piece, which depicts the child as
incomplete, on a site whose own mission says the child is not the problem.
Removing it is the central argument of this redesign.

Also forbidden: spring/overshoot easing, tactile button press, hand-drawn
irregularity, and a fourth accent colour.

## Verification

Claims about rendering must be checked against the rendered page, not against
the source. Contrast in particular: a colour that looks fine routinely fails
measurement. When touching colour, layout or interactive states, load the page
and measure rather than reasoning from the CSS.

Two failure modes worth knowing, both hit during this build:

- `overflow` on `body` makes it the scroll container and silently kills
  `position: sticky` on its children. Clip on `html` instead.
- `position: relative` on `.nav` silently overrides its `sticky`.

## Known gaps

- The contact form has no backend. It validates, then states on screen that
  nothing is sent and gives phone/email instead. Do not imply it submits.
- `site/assets/founder.jpg` is 100×100 and visibly soft at its 104px display
  size.
- The kit photo is representative; the packaging shows placeholder text.
